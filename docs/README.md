## 1. Суть проекта и бизнес-модель

Мы создаём онлайн-платформу персонализированных цифровых подарков с использованием ИИ — **VideoVitannya** (`videovitannya.com.ua`).  
- **Стартовый рынок:** Украина.
- **Языки и SEO-маршрутизация:** украинский (**UA** на каноническом корне `/...`, `308`-редирект с `/uk/...`) и русский (**RU** на отдельных URL `/ru/...` через [src/middleware.ts](file:///g:/WwW/work/gifts-project/src/middleware.ts) и [src/lib/locale.ts](file:///g:/WwW/work/gifts-project/src/lib/locale.ts) с SSR `<html lang="ru">`, локализованными метаданными, `canonical`, `hreflang` `uk` / `ru-UA` / `ru` / `x-default` и [src/app/sitemap.ts](file:///g:/WwW/work/gifts-project/src/app/sitemap.ts)).
- **Единая механика для клиента (видео и сказки):** пользователь заполняет быструю персонализацию (или общается со встроенным ИИ-агентом) → запускает генерацию (исходные фото удаляются из временного хранилища сразу после отработки пайплайна) → просматривает **превью** (пониженное качество + водяной знак; по явной кнопке можно подправить детали с лимитом ИИ-попыток) → указывает Email и оплачивает через **Plata by mono** → получает и сразу смотрит/скачивает на странице заказа готовый чистый HD 720p MP4 (inline-стриминг с HTTP `Range` `206` без превью-водяного знака и без технических меток) или печатный PDF (хранится 30 дней в `/my-orders`, дублируется на Email и в Telegram).

### Архитектура платформы (`src/`, `engine/`, `public/`, `assets/`, `package.json`)
- **Движок, БД, SEO и оплата:** **Next.js 16.2.6 (App Router) + React 19** (`npm run db`, `npm run dev`, `npm run typecheck`, `npm run generate:importmap`, `npm run seed:stage-a`) + гибридная БД: **`Payload CMS 3.84.1` + `PostgreSQL 16`** (`docker-compose.dev.yml`) для настроек ИИ/ElevenLabs, промптов и контента + **`node:sqlite`** для заказов, транзакций **Plata by mono** и аналитики. SEO-роутинг `/ru/...` (`middleware.ts`, `locale.ts`, `sitemap.ts`) + выдача чистых MP4/PDF по `access_token` / верифицированной email-сессии (`30` дней хранения) с inline Range-стримингом HD видео (`?inline=1`, `206 Partial Content`).
- **Админка (`/admin`, Этапы А, Б и конструктор страниц/шаблонов — завершены):** единая Payload-нативная панель (`Payload CMS 3.84.1 + PostgreSQL 16`, русский интерфейс по умолчанию + `RU | UA`, локализация `uk`/`ru` с двунаправленным переводом `RU ↔ UA`, дизайн-система `domainer-platform` / Payload). Легаси `/admin/tariffs` и отдельная коллекция `Faqs` удалены: каталог услуг (включая цены/тиры и свободную область конструктора `extraBlocks`), вариации видео, живые примеры, нелокализуемые отзывы (текст+фото и Instagram embed), блог (`Posts`/`PostCategories`/`Authors` с `PostAiButtons`/`PageSeoButton`), конструктор страниц (`Pages`) и обязательный шаблон главной (`Шаблоны → Главная страница`, всего 22 блока конструктора), вложенное меню (`HeaderNav`/`FooterNav`) и 9 глобалов настроек (включая `AiEconomics` с автообновлением цен из LiteLLM и курса НБУ). Кастомными оставлены только операционные `Дашборд` и `Заказы`. Next.js читает параметры ИИ/ElevenLabs через `getCmsAiConfig()` и передаёт уже синтезированные `.mp3` в stateless Python-сборщик `assemble_pilot.py`.
- **Возврат за заказом и доставка:** вход в `/my-orders` без паролей (6-значный OTP-код + одноразовая magic-ссылка на Email), плюс кнопка **«Надіслати в Telegram»** (`sendDocument`/`sendVideo` для файлов `<= 48 МБ` и защищённая кнопка прямого скачивания для `> 48 МБ`).
- **Рендер видео на сервере:** не требует GPU — фиксированные сцены кэшируются заранее, а на заказ генерируются 3 персональные реплики ElevenLabs + локальная врезка фото и FFmpeg-сборка (~`18 с`).
- **Приватность фото:** EXIF-метаданные удаляются через `sharp` при загрузке, согласие подтверждается отдельно для фото ребёнка и фото родственника (`companionConsent`), а исходные файлы фото удаляются сразу внутри пайплайна по завершении обработки (дополнительно работает TTL-очистка).
- **Встроенный ИИ-агент:** помогает клиенту с выбором подарка, формулировками достижения (лимиты `25–90` символов), кличним відмінком UA и идеями сюжета сказки (промпт `assistant-system` редактируется в Payload).

### Ближайшие шаги и идеи роста
1. **Финализация миграции на Payload CMS и единый PostgreSQL (см. [docs/PAYLOAD_CMS_MIGRATION.md](file:///g:/WwW/work/gifts-project/docs/PAYLOAD_CMS_MIGRATION.md), строго по принципу Payload-first — Этапы А, Б и конструктор на 22 блоках уже завершены):**

   - **Этап Г:** перенос операционных таблиц (`orders`, `email_auth_tokens`, `telegram_tokens`) в тот же `PostgreSQL 16` и полный отказ от `node:sqlite` (одна БД в продакшне).
2. **Полная переработка визуального дизайна платформы под корень (`DESIGN.md`)** поверх блочной и токенной архитектуры.
3. **Доработка промптов картинок (после отката лимита `codex`):**
   - проверить обновлённый живописный промпт (`matte paint, visible painterly brushwork` + `antiRipple` + без `gutter seam`) и сравнить его с более упрощённым/свободным на `gpt-image` (сцены динозавров, ярмарки, теплицы);
   - устранить известные визуальные баги полного промпта **без потери красоты и детализации**: *motif bleed* (дублирование одного орнамента на кружки/лейку/парус/робота), разворот паруса не по курсу лодки и искажение ручек/носиков сложной утвари вроде леек.
4. **Полный аудит логики приложения:** комплексно проверить формы, API-валидации, пайплайны, права доступа, edge-кейсы и связки между шагами (чтобы заранее отловить скрытые логические дыры по аналогии с кейсом питомца/родственника).
5. Настроить реальный Email-транспорт (`RESEND_API_KEY` или `SMTP_*` в `.env.local`) и проверить продакшн webhook.
6. Спроектировать и собрать услугу **«Оживление фото»** (Этап 3), затем песни и открытки (Этап 4).
7. *(Дальняя перспектива — SMM):* **карусели в соцсетях** из готовых сказочных разворотов/историй в качестве постов.

## 2. Текущий воркфлоу производства видео (Этап 1)

1. **Подготовка в чате (Агент + Пользователь):**
   - Продумываем сюжет, структуру, темп монтажа и список шотов ([docs/STORYBOARD_V1.md](file:///g:/WwW/work/gifts-project/docs/STORYBOARD_V1.md)).
   - Готовим консистентные стартовые кадры (`video-pipeline/keyframes/`), motion-промпты и аудио-скрипты (RU / UA).
2. **Генерация видео в браузере (Пользователь в Google Flow):**
   - Пользователь загружает стартовые кадры и motion-промпты в **Google Flow** (**Veo 3.1 Lite**, `8s`).
   - **Ограничение №1 — длительность `8 секунд`:** лишние секунды и моменты с артефактами подрезаются при монтаже.
   - **Ограничение №2 — фильтр по именам святых:** в промптах для видеогенератора **запрещено** упоминать имена святых (*Святой Николай*, *Saint Nicholas*, *Nicholas*) и специфические названия облачения; внешность описывается нейтрально по стартовой картинке.
3. **Монтаж, озвучка и авто-персонализация (`video-pipeline/scripts/assemble_pilot.py`):**
   - **ElevenLabs:** весь ролик озвучивается одним голосом (`NOpBlnGInO9m6vDvFkFC`, `eleven_v4`), а видео-шоты подгоняются и подрезаются точно под движение губ и длину речи (`detect_speech_end` / `find_pauses_and_end`, динамическая длина шота `03` без лишних открытий рта после окончания приветствия и авто-поджатие паузы только для длинных кастомных UA `line_03.mp3 > 6.5 с`) без нейросетевого lip-sync.
   - **Локальный композитинг фото/текста (`Pillow + FFmpeg`):** в шот `04b` на чистую страницу книги врезаются фото (авто-подгонка кропа через `ImageOps.fit` под квадратную рамку), рамка и отмасштабированное имя (с кроссплатформенным фолбэком шрифта на `assets/fonts/georgiai.ttf`); фоновая музыка Suno автоматически приглушается под речь (`sidechaincompress` с `apad=whole_dur`). Временная директория `build/work_<tag>` автоматически удаляется после сборки (если не передан `--keep-work`).
   - **CLI-запуск под заказ:** скрипт принимает `--lang {ru,uk}`, `--tag`, `--name`, `--photo`, `--custom-audio`, `--out` и `--keep-work` (при запуске без аргументов собирает базовые пилоты `RU v9` и `UA v2`).
