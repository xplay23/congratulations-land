## 3. Ключевые выводы на текущий момент и задачи для нового чата

1. **Что уже ясно из сравнения:**
   - **UX и управление книгой** лучше у `ClickerMonkey/StorySpark` (утверждение этапов, перегенерация одного неудачного листа, история картинок, поддержка Replicate/референсов).
   - **Качество первого прогона «из коробки»** (единый книжный `styleGuide`, отсутствие сплит-коллажей, нормальный объём текста 100 слов/стр., готовый кириллический PDF) лучше показала наша надстройка `generate-storybook` + `export.service.ts`.
2. **Чего пока не хватает в обоих решениях для `gifts-project` (Этап 2):**
   - **Персонализация по фото ребёнка** (передача загруженного фото как референса персонажа при генерации иллюстраций, например через `images.edit` / `responses` / Replicate PuLID / InstantID / Flux Kontext / IP-Adapter, чтобы персонаж реально походил на ребёнка, а не был случайной 3D-девочкой).
   - **Выбор и жёсткая фиксация художественного стиля** (акварель, 3D-мультфильм, советская/украинская книжная иллюстрация, карандаш и др.) + защита от сплит-коллажей в промптах.
   - **Двуязычная корректорская проверка (RU / UA)** после генерации текста (устранение редких опечаток падежей вроде `«вёл Мила»`).
3. **План на следующий чат:**
   - Просмотреть ещё несколько open-source генераторов детских иллюстрированных книг (особенно тех, кто делает **character consistency / face personalization по фото**, **portrait+text вёрстку**, **multi-style** и удобный экспорт PDF).
   - После обзора выбрать финальную архитектуру (либо взять UI/workflow одного из лучших репо + наш RU/UA/PDF движок, либо собрать чистый модуль под платформу).

## 6. Зафиксированные решения по платформе и Stage 2 (для нового чата)

1. **Единая воронка для обеих услуг (`Персональное видео` и `Персональная сказка`):**
   - Платформа: **Next.js (App Router)** + **Plata by mono** (+ встроенный ПРРО **Checkbox**).
   - Общий UX-флоу: **`Персонализация → Генерация → Предпросмотр (низкое разрешение + заметный водяной знак) → [Опциональное редактирование по явной кнопке с лимитом попыток] → Оплата → Мгновенная выдача чистого HD MP4 / печатного PDF`**.
   - **Экономика предпросмотра (анти-абьюз и защита бюджета):** чистые исходники (картинки / видео) сохраняются на сервере в приватном хранилище; клиенту до оплаты отдаётся уменьшенная превью-версия с водяным знаком (или для видео — превью-поток), а после webhook `success` от Mono без повторной генерации выдаётся чистый оригинал. На сессию/аккаунт ставится лимит бесплатных превью-генераций и жёсткий лимит ИИ-перегенераций (напр. `2–3` правки на книгу).
   - **Экран редактирования — по явной кнопке** (например, *«Редагувати текст або ілюстрації»*): основной массе покупателей нужен быстрый просмотр → «Оплатить», но желающие могут вручную поправить текст или попросить встроенного ИИ-помощника переписать фрагмент / перегенерировать неудачную иллюстрацию в рамках выделенной квоты.

2. **Два режима вёрстки книги (на выбор при заказе):**
   - **По умолчанию — «Классическая книга»:** иллюстрация и текст на смежных/раздельных страницах (подход `picture-book` / `memorybook`), чистый векторный кириллический шрифт + тематическая акварельная виньетка в правом нижнем углу текстовой страницы. Самый предсказуемый формат для чтения и печати.
   - **Опция — «Панорамный разворот» (`1536x1024`):** единая широкая сцена на две страницы (левая + правая) с чистой центральной зоной 8% (подход `storybloom`), но **в режиме `editable`** (строгий запрет текста внутри генерации нейросети + резерв спокойной зоны «воздуха»/градиента под наложение векторного кириллического текста кодом).

3. **Пошаговый конструктор книги (3 быстрых базовых шага + 2 опциональных за кнопкой «Настроить дальше»):**
   - **Шаг 1 (Обязательный) — Язык, ребёнок и фото *(само фото — опционально)*:**
     - Язык (`UA` / `RU`), имя, пол, возраст (`2–3` / `4–5` / `6–8` лет).
     - Фото ребёнка **необязательно**: если загружено — генерируем канонический портрет-якорь по фото (+ чекбокс согласия родителей); если не загружено — создаём персонажа по имени/полу/возрасту (и при желании базовому выбору внешности: цвет волос/глаз/очки).
   - **Шаг 2 (Обязательный, оба пункта предвыбраны) — Режим вёрстки и Стиль:**
     - Режим вёрстки (`1 из 2`, один уже выбран): **«Классическая книга»** (по умолчанию) или **«Панорамный разворот»**.
     - Художественный стиль (`1 из 4`, один уже выбран по умолчанию). Пользователь может ничего не менять и сразу нажать «Далее».
   - **Шаг 3 (Опциональный по наполнению — со случайным/предвыбранным пресетом) — Сюжет, тон и сеттинг + ГЛАВНАЯ РАЗВИЛКА:**
     - Тон истории, сеттинг и задумка уже предзаполнены случайным/популярным сочетанием (можно перекликнуть пресеты или ввести свой текст).
     - **Основная кнопка:** **`«Создать сказку»`** — сразу запускает генерацию превью (для большинства пользователей путь заканчивается здесь!).
     - **Вторичная кнопка:** **`«Настроить дальше»`** — открывает опциональные шаги 4 и 5.
   - **Шаг 4 (Опциональный, только после «Настроить дальше») — Второй персонаж:**
     - Питомец, член семьи или друг (текстовое описание; загрузка фото — только для своей семьи/питомцев, см. юридику в п. 5).
   - **Шаг 5 (Опциональный, только после «Настроить дальше») — Любимая игрушка / предмет *(+ опционально посвящение на титуле)***:
     - Фиксируется в `Visual Bible` (`RECURRING TOY LOCK`), чтобы предмет оставался неизменным на всех страницах.

4. **3-шаговый писательский пайплайн (RU/UA):**
   - *Шаг 1:* План-биты (завязка → открытие → препятствие → кульминация → тёплая развязка);
   - *Шаг 2:* Черновик + короткая «анти-ИИ» редактура (живые детали, ритм для чтения вслух, без шаблонных нравоучений);
   - *Шаг 3:* Обязательный корректор RU/UA (падежи, род, звательный падеж UA).

5. **Приватность и юридика фото ребёнка (и второго персонажа):**
   - Удаление EXIF до отправки, хранение оригинала только на время генерации якоря/книги (TTL авто-удаления), платные API-тарифы OpenAI / Google (без обучения моделей на входных фото), явное согласие родителя.
   - **Фото чужого ребёнка (друг на Шаге 4):** по ЗУ «Про захист персональних даних», ст. 307–308 ЦКУ и GDPR устное согласие «от чужих родителей со слов клиента» юридически недоказуемо и уязвимо для платформы. Безопасное решение: **для друга разрешать только текстовое описание (имя, пол, внешность)**, а загрузку фото ограничивать **собственным ребёнком, членами своей семьи (по их согласию) и питомцами**.
