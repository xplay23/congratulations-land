Первоначальный полностью чёрный кадр удалён из веб-копий; оставлен весь остальной видеоряд, 49,04 с. Все четыре копии содержат ровно одну видеодорожку и ни одной аудиодорожки, проверено ffprobe.
- Сначала отображается первый нечёрный кадр (кадр № 1, примерно 0,042 с, начало исходного fade-in). AVIF/WebP/JPEG: 640, 960 и 1280 px. AVIF 1280 px — 14 414 байт. Изображение имеет высокий приоритет, видео начинает загрузку после готовности страницы и декодирования плейсхолдера. При отсутствии JS остаётся изображение.
- WebM/VP9 — основной видеоформат, MP4/H.264 — нативный fallback. До 640 CSS px выбирается 480p, иначе 720p. В старых браузерах без поддержки `media` у `<source>` возможен выбор первого поддерживаемого 480p-файла. JS-полифилы не требуются. MP4 имеет faststart; production поддерживает HTTP 206/416 и HEAD для обоих форматов.
- При reduced motion или Save-Data видео не запрашивается до нажатия кнопки. Автопауза при скрытии вкладки/выходе из первого экрана, ручная пауза сохраняется. Если медиа не воспроизводится, остаётся плейсхолдер.
- Все используемые фотографии каталога и блока истории имеют AVIF/WebP/JPEG, `srcset`, `sizes`, размеры и `decoding="async"`. Изображения ниже первого экрана загружаются лениво, продуктовый hero — с высоким приоритетом. SVG-логотипы сохранены в векторе, OG — в JPEG для совместимости соцсетей. Превью загруженных пользователем файлов не перекодируются.
- HTML/CSS/JS/SVG/XML заранее сжимаются в Brotli и Gzip. HTML остаётся с `no-cache`; ресурсы Vite с хешами — год и `immutable`, медиа — 30 дней. При замене медиа после публикации нужно менять имя файла. Query-страницы сохраняют `noindex` и выдаются без предсжатия. На стороннем static hosting настройку сжатия и кеша нужно перенести в конфигурацию хостинга.
- Основные локальные Rubik-шрифты предзагружаются. Форма заказа выделена в отдельный JS-файл и предварительно загружается только на страницах с формой.
- Устранён forced reflow в шапке: состояние прокрутки отслеживается через IntersectionObserver.
- `public/robots.txt` и генерируемый `dist/sitemap.xml` доступны также через dev-сервер. Sitemap исключает noindex-страницы, включая кабинет, оплату, результат и заказ. Блог скрыт только из интерфейса согласно предыдущему запросу; индексируемые статьи остаются в карте.

## Оставшиеся рекомендации

Lighthouse отмечает общий объём автопроигрываемого 49-секундного видео. Для дальнейшего заметного сокращения потребуется сократить ролик или отказаться от автозапуска. Сохранён полный ролик. Стили размером около 7 КБ по сети остаются блокирующими отрисовку, чтобы переходы не показывали неоформленную страницу и белый блик; оценка потенциальной экономии — около 140–150 мс на мобильном профиле. Короткая цепочка HTML → CSS/JS также остаётся в диагностике. Не все диагностические рекомендации устранены.

## Повторная проверка

```powershell
npm run build
npm test
# При необходимости укажите путь к уже установленному Chromium:
$env:PLAYWRIGHT_CHROMIUM_EXECUTABLE = 'C:/Users/Mykhailo/AppData/Local/ms-playwright/chromium-1252/chrome-win64/chrome.exe'
npm run audit:performance -- current --all
```

Скрипт поднимает свой production-сервер на 5188, запускает Chromium с CDP на 9223 и закрывает оба по завершении. Порты должны быть свободны. HTML и JSON отчёты находятся в `tmp/lighthouse/<метка>/`; итоговый замер этой работы — `final`. Отчёты не включаются в исходный код. Медиа воспроизводимо собираются через `scripts/prepare-background.py` (аргументы: исходный MP4, путь к FFmpeg) и `scripts/prepare-images.py` (Pillow с поддержкой AVIF). FFmpeg скачан со сборок Gyan, на которые ссылается официальный сайт FFmpeg; исполняемые файлы находятся только в игнорируемой папке `tmp/`.

Браузерные проверки включают отсутствие загрузки видео при reduced motion, воспроизведение и паузу, MP4/JPEG fallback, robots/sitemap, Brotli, byte ranges, навигацию без JS и задержанную загрузку CSS. Проверки выполнялись в Chromium с desktop/mobile viewport; отдельный прогон Safari/WebKit не выполнялся.

Методология: [Lighthouse](https://developer.chrome.com/docs/lighthouse/overview), [оптимизация видео](https://web.dev/learn/performance/video-performance).
